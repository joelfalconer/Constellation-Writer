# Scope and Non-Goals

## In scope for the foundation release

- Editor shell and professional interaction doctrine.
- Project vault and canonical file contracts.
- Sheet identity, text, and metadata model.
- Manuscript assembly and binder projection.
- Literal and structural recall.
- Deterministic compile and QA contract.
- Atomic writes, autosave, snapshots, archives, conflicts, and restore.
- Governed mutation and PatchSession substrate.
- Minimal Compendium boundary: entity, claim, evidence, and current-Sheet inspection.
- Reference fixtures, validators, and failure-injection tests.

## Explicit non-goals

- Real-time multi-user collaboration.
- Cloud-only storage or required account login.
- Plugin dependency for core writing.
- Graph-first navigation.
- Block-editor manuscript bodies.
- AI ghostwriting as the primary product identity.
- Full publishing-layout replacement for Vellum or InDesign in the first release.
- Universal PKM or second-brain workflows.
- Full franchise operations, timelines, motif maps, or semantic graph exploration in v1.

## Scope change rule

A proposed addition must identify the user problem, canonical state impact, dependency direction, recovery behavior, performance cost, acceptance test, and feature displaced by the added scope.
