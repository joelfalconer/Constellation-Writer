# ADR-0001: Contract-First Foundation Programme

**Status:** proposed

## Decision

Establish the project through constitution, shared contracts, reference fixtures, an executable vertical slice, and failure injection before treating component specifications as accepted architecture.

## Rationale

Independent long-form specifications encourage duplicated principles, status drift, and ambiguous ownership. Shared contracts make later documents views over one system.

## Consequences

- Candidate specs must be decomposed and reconciled.
- The first build proves the whole canonical loop rather than maximizing feature breadth.
- Documentation is versioned alongside schemas, fixtures, and tests.

## Revisit trigger

Revisit only if the contract-first sequence materially prevents testing the editor’s daily-use value.
