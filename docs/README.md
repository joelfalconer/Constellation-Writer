# Documentation Map

## Programme

Project purpose, scope, outcomes, deliverables, gates, risks, and execution contracts.

## Constitution

Highest-authority product laws, canonicality, state ownership, invariants, and terminology.

## Architecture

System model, mutation substrate, dependency direction, boundaries, and implementation views.

## Decisions

Architecture Decision Records and the decision ledger.

## Specifications

Reconciled component specifications. These import constitutional invariants and shared contracts rather than redefining them.

## Validation

Fixtures, assays, failure-injection protocols, performance budgets, and gate receipts.

## Status vocabulary

- `draft`: incomplete working material.
- `candidate`: coherent proposal awaiting validation or review.
- `accepted`: approved project contract.
- `tested`: exercised by deterministic or prototype validation.
- `superseded`: retained for lineage but no longer active.
